## 1. Operator Physical Verification Checklist [OPERATOR TEST REQUIRED]

The automated code, integration, security, voice, and packaging test suite is 100% verified (193/193 tests passing). The following physical device and external cloud checks cannot be automated in this headless Windows environment and require manual operator execution:

### A. Android Companion Physical Device Pairing [OPERATOR TEST REQUIRED]
1. **Prerequisites:** Connect the Windows PC host and the Android mobile phone to the same trusted local Wi-Fi router / subnet.
2. **Step 1 (Host Enable):** Open the J.A.R.V.I.S. Dashboard on the PC (`http://127.0.0.1:8000/app` or right-click the Floating Companion widget) and navigate to **Settings -> LAN Pairing**.
3. **Step 2 (Enable Mode):** Click **Enable LAN Pairing Mode**. The server binds to `0.0.0.0:8000`, generates a cryptographic 8-character pairing key, and displays a QR code pointing to `http://<LAN_IP>:8000/app`.
4. **Step 3 (Phone Connect):** On the Android phone, scan the QR code or navigate to `http://<LAN_IP>:8000/app` in Chrome.
5. **Step 4 (Pairing Validation):** Enter the 8-character pairing code. The server performs PBKDF2 (200,000 rounds) key derivation and issues an AES-256-GCM authenticated session token.
6. **Step 5 (Voice Stream Verification):** Tap the microphone button on the phone web interface. Verify that the browser requests microphone permission and streams audio over WebSocket (`/ws/phone-audio`) to the host PC's Faster-Whisper STT queue.
7. **Step 6 (Security Verification):** From the phone browser, attempt to navigate to `http://<LAN_IP>:8000/api/reels` or `http://<LAN_IP>:8000/config`. Confirm that the server returns HTTP 403 Forbidden due to `_RESTRICTED_LAN_PREFIXES`.

### B. Wake-on-LAN (WoL) Physical Network Verification [OPERATOR TEST REQUIRED]
1. **Hardware Prerequisite:** Verify that the PC motherboard BIOS/UEFI has "Wake-on-LAN" (PME Event Wake Up / PCIe Wake) enabled, and Windows Device Manager network adapter properties have "Allow this device to wake the computer" and "Only allow a magic packet to wake the computer" enabled.
2. **Limitation Note:** When the PC is completely shut down (ACPI S5) or sleeping (S3), the Python process and HTTP server are suspended and cannot receive HTTP requests.
3. **Execution:** Send a UDP Wake-on-LAN Magic Packet (broadcast to port 9 with the PC's MAC address `6x FF + 16x MAC`) from an Android WoL app (e.g. "Wake on Lan" by Mike Webb) to verify hardware wake.
4. **Software Sleep/Wake:** While J.A.R.V.I.S. is running, test the companion sleep/wake toggle via `/api/action` (`{"action": "sleep"}` / `{"action": "wake"}`) from the paired companion dashboard.

### C. Clean-Machine Distribution Testing [OPERATOR TEST REQUIRED]
1. **Prerequisite:** Prepare a clean secondary Windows 10/11 x64 PC (or a clean Hyper-V / VirtualBox Windows VM) with NO existing Python, Git, or Ollama installed.
2. **Installer Test:** Copy `JARVIS_Mark_LVI_Setup.exe` (2.83 MB) to the target machine.
3. **Execution:** Run the installer executable. Verify that the Inno Setup wizard guides through installation, creates Start Menu and Desktop shortcuts, and unpacks the 183 core files into `C:\Program Files\JARVIS Mark LVI` (or chosen directory).
4. **Environment Initialization:** Run `install_jarvis.bat`. Verify that it prompts for Python 3.10+ (if absent) with official download link, or automatically discovers local Python to initialize `.venv` and install `requirements.txt`.
5. **Launcher Test:** Double-click `launch_jarvis.bat`. Verify that the launcher discovers Python without `'LOCAL'` or `'python'` errors, starts the host service on `http://127.0.0.1:8000/app`, and opens the companion UI.
6. **Portable ZIP Test:** Extract `JARVIS_Mark_LVI_Windows_x64_Portable.zip` into a standalone folder and run `launch_jarvis.bat`. Verify that all 183 files match `SHA256_MANIFEST.txt` 100%.
